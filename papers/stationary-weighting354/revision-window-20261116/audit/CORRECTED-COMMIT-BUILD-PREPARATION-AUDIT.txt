REMAINING BLOCKER B1: COPY ERRORS DO NOT RELIABLY FAIL THE PACKAGING STEP

The diagnostic packaging command is structurally:
find . -type f ! -name '*.png' ! -name '*.pdf' -exec cp --parents -- '{}' "$bundle/diagnostics/" \;

The document packaging command has the same -exec ... \; form for PDF/PNG.

In GNU find, this form uses the invoked command's result as the truth value of the predicate. A nonzero cp exit does not by itself force find to return nonzero. A false predicate is a normal evaluation outcome. Thus the shell's set -e can see a successful find process even when some file copies failed.

Concrete failure path: a source log is unreadable, disappears between selection and copying, or cannot be fully copied into the bundle; cp returns nonzero, while find finishes its traversal normally. The script then measures the incomplete bundle, may emit 'full text diagnostics retained' or 'Document included', sets upload_ok=true and uploads the partial result. The failure is not represented as packaging failure. A partial PDF/PNG bundle can likewise be labeled included after the pipeline's page-count check passed on the original directory. The pipeline check therefore does not catch a later packaging omission.

This is not an assertion that such an error has occurred or will occur. It is a precise unchecked-exit defect in the preparation, directly relevant to the guarantee being added. It also affects the large-diagnostics console fallback: that fallback reads the copied bundle, so files omitted during copying cannot be recovered there.

Minimal correction direction: use a copying form whose process failure propagates, for example GNU find -exec cp --parents -t TARGET -- {} +, which documents a nonzero find status when any invoked command fails. Capture that failure explicitly, retain a packaging-failure record, and do not claim a complete bundle. If fallback is used after an incomplete copy, it must read the original available diagnostic files, not assume the partial copy is complete. Keep the same capacity limit and truthful incompleteness status. A source-to-bundle file/hash inventory is an additional clear way to establish exact copied payload completeness; this report does not require new scientific tests or a runtime just to prepare the correction.

Primary reference: GNU find manual as shipped by Debian, ACTIONS section:
https://manpages.debian.org/bookworm/findutils/find.1.en.html
It distinguishes the single-command predicate's truth value from the '+' form's propagation of command errors into find's process status. The proposed correction relies on that documented distinction. This was checked by reading documentation, not by executing a reproduction.
